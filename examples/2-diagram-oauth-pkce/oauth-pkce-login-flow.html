A

Authorization code flow with PKCE

RFC 6749, RFC 7636, nextjs-auth0 4.31.0 defaults

The Next.js server is the OAuth client. At step 2 it makes a secret code_verifier. Only its hash, code_challenge, goes to Auth0 in the step 4 URL. At step 10 the server sends the code together with code_verifier. Auth0 returns tokens only if the hash of code_verifier is equal to code_challenge. Your API sees only the access_token and validates it at step 19.

The cookie also expires after 1 h. A callback URL that you open a second time gives this error too, because step 14 deleted the cookie.Start the login on the host of APP_BASE_URL. 10access_denied: UnauthorizedAUTH0_CLIENT_ID or AUTH0_CLIENT_SECRET does not agree with the application in this tenant.Copy both values again from the application settings in Auth0.
10invalid_grant: Invalid authorization codeAuth0 already used this code, or the code is older than 10 min. Two requests to the same callback URL at the same time can also cause it.Start a new login. In the Network tab, find the second /auth/callback request.
11invalid_grant: Failed to verify code verifierThe code_verifier of step 10 does not give the code_challenge of step 4. Auth0 states that several fast /authorize calls for one login cause it.Start the login one time only. If your own code makes the PKCE values, compare BASE64URL(SHA256(code_verifier)) with code_challenge in the step 4 URL.
16missing_refresh_token from getAccessToken()The access_token expired (default 24 h), and the session has no refresh_token. Auth0 gives one only with offline_access in the scope and Allow Offline Access enabled for the API.Keep offline_access in the scope. Enable Allow Offline Access in the API settings in Auth0.
18API 401. The token payload does not decode as JSON.Step 4 had no audience. Auth0 then returns an opaque token that only /userinfo accepts.Set authorizationParameters.audience in Auth0Client to the API identifier. Then log out and log in again, because the old session keeps the old token.
19API 401: aud or iss is not correctaud must be equal to the API identifier. iss is https://<AUTH0_DOMAIN>/ with the slash at the end. With a custom domain, iss contains that domain.Decode the token. Compare aud and iss with the values in the API configuration.
19API 403: insufficient_scopeThe token does not contain the scope or the permission that the endpoint needs.Add the scope to authorizationParameters.scope. For RBAC permissions, enable Add Permissions in the Access Token in the API settings.

The SDK shows a callback error as a 500 response with a short message. The Auth0 error is in error.cause. Log it in the onCallback hook of Auth0Client.

The route /auth/access-token gives the token to browser code. If the browser calls your API directly, the access_token is in browser JavaScript, and your API needs CORS.
